# 品牌矩阵GEO

通用模板。事实同源、表达分渠；禁止一套文案群发；禁止编造事实与销量。

## 0. 目标
让生成式引擎在相关回答中准确提及、引用、推荐该品牌。优化实体与证据链，不是堆关键词。

成功指标（分引擎记账）：提及率、引用准确率、实体一致性、矩阵覆盖率、转化（有数据才写）。

## 1. 引擎覆盖清单（Skill 内置；执行时按品牌勾选）

### 1.1 国内主流（默认全开，除非用户删）
| 引擎 | 厂商/入口 | 抽检方式 |
|---|---|---|
| 文心一言 | 百度 | Web/App 问答抽检 |
| 通义千问 | 阿里 | 同上 |
| 豆包 | 字节 | 同上 |
| Kimi | 月之暗面 | 同上 |
| DeepSeek | DeepSeek | 同上 |
| 智谱清言 (GLM) | 智谱 | 同上 |
| 腾讯元宝 | 腾讯 | 同上 |
| 讯飞星火 | 科大讯飞 | 同上 |
| 百度 AI 搜索 / 文心搜索 | 百度 | 搜索型回答 |
| 纳米 AI / 其他新兴 | 按需 | 标可选 |

### 1.2 跨境/国外主流（跨境或品牌要出海时默认全开）
| 引擎 | 说明 | 抽检方式 |
|---|---|---|
| ChatGPT | OpenAI | 问答抽检 |

执行规则：
- 纯国内品牌：国内清单必做；国外清单做精简版（ChatGPT、Perplexity、Gemini 至少抽检）。
- 跨境/出海：两套全做，英文实体主档与中文主档事实对齐。
- 每个引擎单独渠道卡 + 单独抽检记分，禁止合并成「国内AI」一笔糊涂账。

## 2. 品牌输入包
法定名/别名/口号；定位人群边界；产品价档；≤3差异化（要证据）；案例；全渠外链；视觉与合规；转化路径；竞品；**国内/跨境模式**；分渠偏好。
输出：`品牌实体主档.md`（中文；跨境另出 `Entity-Record.en.md`）。

## 3. 实体图谱
品牌/产品/品类/场景/框架/人物/竞品/合作方/证据。字段含覆盖分、P0–P3、主投放引擎与渠道。

## 4. 分引擎 × 分渠道策略卡（必做）
每引擎/每渠道一张卡：目标、形态、结构、语气、长度频率、CTA、外链、对齐检查、3道抽检题、禁止事项。

### 4.1 引擎方向要点
- ChatGPT/Claude：可摘录定义+步骤+边界；中性专业；软CTA
- Gemini/AI Overviews：与可检索网页一致；短要点
- Perplexity/Copilot：出处与链接感；可核验
- 文心/通义/豆包/Kimi/DeepSeek/清言/元宝/星火：中文场景词、国内品名一致、本地案例、口语FAQ
- 内容渠道（官网公众号视频号抖音快手小红书B站YouTube X知乎百科朋友圈）：沿用既有分渠表，一鱼多吃须按卡改写

## 5. 内容矩阵
查询类型（认知/场景/对比/证据/产品/FAQ）×（每个勾选引擎 + 每个内容渠道）。空白格→backlog。

## 6. 写作规范
答案前置；问题式标题；自洽段落；表格步骤；具名日期；可核验来源；术语=主档；FAQ；CTA按渠；schema能上就上。

## 7. 交付物
实体主档（+英文若跨境）、矩阵热图、backlog、全量引擎卡与渠道卡、大纲与分渠成稿、一致性摘录包、脚本包、**分引擎题库30–50题**、90天日历、复盘看板、**跑批抽检报告**。

## 8. 自动化与抽检
阶段A：选题映射到具体引擎/渠道空格；母稿；分渠改写；简介diff；题库分引擎跑批。
阶段B：n8n/Dify 定时抽检（API待验证处标注）。
抽检报告字段：引擎、题号、是否提及品牌、是否事实正确、是否提及竞品、原文摘录、改进动作。

## 9. 节奏
Week0主档+矩阵+写齐卡；Week1–2补P0；Week3–4外链一致+首轮分引擎抽检；月更；季更。

## 10. 门禁
实体零冲突；符合对应卡；非群发改标题；证据成立；已入对应引擎题库。

## 11. 运行时
1. 先确认国内/跨境模式与勾选引擎列表。
2. 缺事实就停。不编造。
3. 大产出落盘。
4. 品牌私密不写回 Skill。
5. 「用某品牌跑一遍」时：调研公开信息→主档→分渠卡→矩阵与P0样稿（至少六大信息块各1）→题库→模拟/真实抽检表→给用户路径与待确认清单。

## 12. 一键生成：30 天 GEO 运营计划（用户说「XX品牌国内/跨境GEO30天运营计划」即触发）
无需追问即开跑：读已有品牌资料（若无先按第11节跑主档），缺事实标「待确认」继续产出。

### 12.1 范围
- 国内模式：引擎=文心一言、通义千问、豆包、Kimi、DeepSeek、智谱清言、腾讯元宝、讯飞星火、百度AI搜索；渠道=官网/落地页、公众号、视频号、抖音、快手、小红书、B站、知乎、百度百科/百家号/知道、电商详情页（淘宝/京东/拼多多/抖店按确认）、朋友圈私域。
- 跨境模式：ChatGPT、Claude、Gemini、AI Overviews、Perplexity、Copilot；渠道=英文官网、Amazon/独立站详情、YouTube、Reddit、Quora、LinkedIn、X、Medium、Wikipedia/Wikidata（合规条件下）、行业目录。
- 每引擎/渠道单独方向，禁止群发。

### 12.2 四周骨架（按品牌改写主题）
- W1 实体奠基：主档定稿、消歧、权威页、详情页七要素、Day1 分引擎基线抽检
- W2 知识与场景：知乎/百科/公众号（跨境：Reddit/Quora/博客）定义、场景、方法文
- W3 种草与证据：小红书/抖音/视频号（跨境：YouTube/社媒）场景内容 + 检测、授权口碑证据包
- W4 对比与FAQ加固：对比表、异议FAQ、Day15 中期复测后补洞、Day30 复测与下月计划

### 12.3 每日计划字段（Day1–30 必填）
日期 | 周主题 | 当日目标 | 引擎动作 | 各渠道具体标题（写出真实标题）| 形态 | 负责人（品牌方/内容/增长/AI助手）| 产出物 | 验收标准 | 依赖物料 | 状态

### 12.4 必含 Sheet / 章节
总览、每日计划、引擎动作表、渠道内容表、抽检记分表（Day1/15/30，空表不编造）、物料清单（含截止日）、KPI（可衡量指标+假设区间）、人力两档（最小/标准，按工时与篇数，不报价格）、合规红线。

### 12.5 行业合规
食品/保健：不写疗效、治病、保健功能承诺；医疗/金融/教育等按行业红线另列。无证据主张一律删除。

### 12.6 输出
`/workspace/<品牌>_<国内|跨境>GEO_30天运营计划.xlsx` + 同名 `.docx`（标题思源宋体、正文思源黑体，用户品牌色）。回报：路径、每周一句话、前7天要点、待确认物料。

## 13. 一站式品牌输入表 → 自动分析（第1、2步的标准入口）
**零资料一键模式（默认）**：用户只给品牌名（或品牌名+品类）即可，不要求提交任何资料、不追问。执行顺序：
1. 自动检索公开信息（官网、电商店铺、工商/企查查公开信息、百科、媒体报道、社媒账号、AI引擎当前回答）自动填满输入表全部字段；
2. 每个字段标来源：【公开可查+链接】/【行业通用推断】/【待补】，推断只用于品类共性（如品类常见人群、场景），不得推断资质、检测、销量、功效、公司事实；
3. 直接从第一步（输入表）连续生成到第二步（实体图谱/主档）及13.2全部分析，一份报告一次交付；
4. 报告末尾附「建议补充资料」清单，补了可一键重跑提升准确度。
用户若主动提供资料，以用户资料为准覆盖检索结果。

### 13.1 输入表字段
| 区块 | 字段 |
|---|---|
| 品牌 | 品牌名/别名、品类、一句话定位、**品牌简介**（理念、历史、故事）|
| 公司 | **公司简介**（主体名称、成立时间、所在地、规模、主营、产地/工厂）|
| 资质 | 主体、商标、生产许可SC/备案号、执行标准、检测报告、认证（有机/地标等）、授权背书 |
| 产品结构 | **引流款**、**主推款**、**利润款**、**价值款（形象/高端）**、**经典款**；每款：名称、规格、价格、成本区间（可选）、渠道 |
| 卖点 | 核心卖点（用户原话）、原料/产地/工艺、差异化、证据 |
| 基础信息 | 保质期、储存、食用/使用方法、禁忌与不适宜人群 |
| 用户 | 适合人群（可多组）、使用场景（可多条）、购买动机 |
| 竞品 | 3–5个竞品及价格 |
| 渠道 | **主要销售渠道**（天猫/京东/抖店/拼多多/视频号小店/私域/线下/跨境站点，各渠道占比与主推款）、内容渠道、国内/跨境 |

### 13.2 自动分析输出（固定顺序，一次呈现）
1. **品牌实体主档**（官方唯一表述 + 消歧）
2. **产品矩阵分析**：五类款定位表（角色、价格带、毛利角色、对应人群、对应渠道、内容打法）、款间关联销售与升单路径
3. **人群画像**：每组人群的痛点、动机、顾虑、决策触发点
4. **场景自动解析**：人群×场景矩阵；每个场景写「时间-地点-情绪-问题-产品解法-一句话文案」
5. **卖点提炼**：FAB（属性-优势-利益）+ 证据等级（A有检测/B有来源/C主张待证）；核心卖点≤3，辅助卖点≤5；每条卖点给不同渠道的说法
6. **价值感塑造**：价格锚点、成本/工艺可视化、稀缺与时令、仪式感、礼赠价值、对比替代品算账、社会认同（仅真实）
7. **写作规范**：品牌语气、必用词、统一术语、标题公式、开头钩子（短视频开头15秒极吸睛，标题与封面文字不同）、分引擎/分渠道写法
8. **注意事项**：品类合规要点（食品/保健/化妆品/医疗器械/教育/金融分开列）、平台规则、证据缺口
9. **敏感词与替换表**：极限词（最/第一/顶级/国家级…）、医疗功效词（治疗/治愈/降血糖/抗癌/调理疾病…）、虚假承诺、迷信与不当用语；给「禁用词 → 安全替换」对照，并标适用法规（广告法、食品安全法相关条款，标「以最新法规为准」）
10. **全渠道作战包**（四块，全部自动生成，接续第2–12节）：
   - **10A 销售渠道策略卡**（每个销售平台一张：天猫/淘宝、京东、抖音电商、快手电商、拼多多、视频号小店、小红书店铺、私域/社群、线下商超/礼品渠道；跨境加 Amazon、TikTok Shop、独立站、Shopee/Lazada）
     每卡字段：平台人群与流量逻辑、**营销打法**（搜索/货架/直播/达人/投放/活动节点/会员）、**价格带**（平台主流价格带、本品各款应放的价位与定价理由、券后价与活动价）、**人群细分**（该平台核心人群×购买动机×对应款）、**竞品分析**（该平台TOP3–5竞品：价格、主卖点、销量级别【公开可查才写】、评价痛点、我方差异化打法）、主推款/引流款分配、KPI。
   - **10B 内容矩阵**（各内容平台一张：抖音、快手、视频号、小红书、B站、知乎、公众号、百家号/头条、微博、百度百科/知道；跨境加 YouTube、TikTok、Instagram、Reddit、Quora、Medium、Wikipedia类）
     每卡字段：**内容差异原理**（推荐机制：兴趣/社交/搜索/关注）、**平台规则**（时长、字数、标签、外链、营销限制、违规红线）、**打法**（选题类型、钩子公式、结构模板、发布频率与时段、账号矩阵、互动与引导转化方式）、对应卖点和场景、示例标题×3（标题与封面文字不同，开头15秒强钩子）。
   - **10C 主流AI平台GEO规则卡**（国内：文心一言/百度AI搜索、通义千问、豆包、Kimi、DeepSeek、智谱清言、腾讯元宝、讯飞星火、360/纳米AI搜索、秘塔；跨境：ChatGPT、Claude、Gemini/AI Overviews、Perplexity、Copilot、Grok）
     每卡字段：**风格喜好**（偏好的回答结构、引用来源偏好如百科/知乎/公众号/官网/权威媒体）、**规则与要求**（可引用内容特征：结构化、数据、FAQ、实体一致、时效）、**敏感词**（该平台高风险话题与词）、**边界**（不会推荐/会拒答的情形、医疗健康与绝对化表述的处理）、我方应铺设的信源与内容形态、采样问题×5。规则基于公开资料与实测采样，标注「观察结论，非官方规则」。
   - **10D 30天计划**：按第12节一键生成，任务须同时引用10A/10B/10C的卡片编号，做到每天「哪个平台-发什么-服务哪个引擎-对应哪个卖点/款」。
   交付：`全渠道作战包.xlsx`（分表：销售渠道卡/内容矩阵/AI平台规则/30天计划）+ 并入一站式分析报告.docx。

### 13.3 交付文件
- `/workspace/<品牌>_GEO一站式分析/品牌输入表.xlsx`（已填+待补高亮）
- `.../一站式分析报告.docx`（上述1–9全部）
- `.../敏感词替换表.xlsx`
- 回报：缺项清单、最需要补的3项证据、下一步建议

### 13.4 规则
- 不编造资质、检测、销量、功效；用户未提供即「待补」。
- 食品类一律不写疗效与疾病预防治疗；用「口感/冲泡/日常饮用/搭配」等安全表达。
- 空白模板：执行时若用户要模板，先输出空白输入表给其填写。

## 14. SEO 基础检查（与 GEO 一并诊断）
GEO 与 SEO 并列执行。零资料一键时自动做，输出并入一站式报告。

### 14.1 检查项
| 项 | 查什么 | 过线标准（公开可查） |
|---|---|---|
| 收录 | site:品牌域名 / 品牌名 | 有稳定收录页 |
| 官网/品牌页 | 是否存在、HTTPS、移动端 | 有可打开的品牌落地页 |
| 标题与描述 | title、meta description | 含品牌+品类，不堆砌 |
| 结构化数据 | Organization/Product/FAQ/LocalBusiness | 有 JSON-LD 或等效标记则记「有」 |
| FAQ/问答页 | 品牌 FAQ、场景问答 | 至少一组可被 AI 引用的问答 |
| 内链与导航 | 产品/场景/关于我们 | 关键实体页互相可达 |
| 外链与信源 | 百科、媒体、权威站提及 | 列可核实链接；无则「待补」 |
| 图片与 ALT | 主图是否带品牌名 ALT | 记有/无 |
| 速度与体验 | 首屏是否可用（粗测） | 明显卡顿标风险 |
| 本地/门店 | 若有线下：地图、地址一致 | NAP 一致 |

### 14.2 输出
- SEO 体检表（红黄绿）+ 与 GEO 的联动建议（哪些页先改才能被 AI 引用）
- 优先修复 Top5（和 GEO 的 P0 合并排序）
- 不保证百度/谷歌排名；不编造收录量

`/workspace/<品牌>_GEO一站式分析/SEO基础检查.xlsx` 并入报告.docx

## 15. 落地方案：AI平台收录倒推 × 内容矩阵铺设 × 90天计划
一站式默认交付「30天」后，必须再出「90天落地」；用户说「落地方案/铺矩阵/怎么收录」时直接执行本节。

### 15.1 每个AI平台：内容如何被「规划收录」（可引用）
对每个国内/跨境引擎输出一张「收录倒推卡」（观察结论，非官方规则）：
| 字段 | 说明 |
|---|---|
| 引擎 | 如豆包/DeepSeek/元宝/文心/Kimi/通义/ChatGPT… |
| 偏好信源 | 百科、官网、权威媒体、知乎、公众号、小红书、电商店铺、学术等（按公开观察排序） |
| 可引用内容形态 | FAQ、对比测评、结构化列表、带日期的事实页、门店/SKU页 |
| 收录/引用路径 | 「先被搜索引擎或平台收录 → 再进入训练/检索增强 → 出现在回答」的倒推步骤 |
| 更新节奏 | 该引擎对时效内容的敏感度（高/中/低） |
| 品牌应铺的内容类型 | 实体页、场景问答、对比消歧、活动口径（带日期） |
| 禁区 | 该引擎高风险话题与敏感词边界（接第10C） |
| 采样题 | 5道，用于验证是否被正确理解/提到/推荐 |

规则：不承诺「一定收录」；写「提高被引用概率的动作」。

### 15.2 倒推：对应内容平台怎么铺矩阵
根据 15.1 的信源偏好，反推内容平台优先级与打法：
1. **P0 信源台**（决定「被理解」）：官网/品牌页、百科、结构化 FAQ、权威媒体稿
2. **P1 讨论台**（决定「被提到」）：知乎、百家号/头条、公众号、搜狐/网易号、行业垂直站
3. **P2 种草台**（决定「被推荐给消费者」）：小红书、抖音、视频号、B站（按品类取舍）
4. **P3 交易台**（决定「带链接的事实」）：天猫/京东/抖店等详情页与评价口径统一

每个内容平台输出：目标引擎（服务谁）、内容栏目（每周几条什么类型）、标题公式、是否外链、负责人/频率、与销售渠道卡的关联。

### 15.3 90天计划（默认交付，可与30天并存）

- **Day31–60｜占位**：场景与对比内容放量、P2 种草、竞品消歧、双周复测、根据提及率调词
